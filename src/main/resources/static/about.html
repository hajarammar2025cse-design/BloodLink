About BloodLink

Academic Full-Stack Project • Spring Boot + MySQL + Vanilla Web

1. Problem Statement & Objective

In critical medical situations such as emergency surgeries, vehicular trauma, or thalassemia treatments, locating a willing and medically eligible blood donor with the required blood group is often a race against the clock.

Most standard community blood directories suffer from two critical flaws:

  1. They list donors who have donated very recently, resulting in frantic calls to donors who are medically banned from donating.
  2. They require manual administrative intervention to reactivate donors once their recovery duration ends.

BloodLink's Objective: Maintain an automated, medically safe donor registry that calculates eligibility dynamically in the backend service layer, hides donors during their 90-day cooldown period, and re-enables them automatically the moment 90 days elapse.

2. The 90-Day Medical Cooldown Business Rule

Core Rule

According to World Health Organization (WHO) and National Blood Transfusion Council guidelines, a minimum interval of 90 days (approx. 3 months) must be maintained between whole blood donations to allow the donor's body to replenish red blood cells and iron stores safely.

Backend Implementation Architecture:
public boolean isEligible(Donor donor) {
    if (donor.getLastDonationDate() == null) {
        return true; // Never donated -> Eligible
    }
    LocalDate eligibleDate = donor.getLastDonationDate().plusDays(90);
    return !LocalDate.now().isBefore(eligibleDate);
}

Key Guarantees:

  • Service-Layer Enforcement: Frontend validation is treated as a visual aid. The Spring Boot backend service layer strictly enforces the rule and rejects illegal donation attempts with HTTP 400 Bad Request.
  • Zero Deadlocks: When dates progress beyond 90 days, the donor status dynamically switches to available = true without any manual admin clicking.
  • Search Isolation: Search queries filter out candidates who are still within their 90-day cooldown window.

4. REST API Reference

Method Endpoint Description
GET /api/donors List all registered donors with live cooldown status
GET /api/donors/{id} Retrieve single donor by primary key ID
POST /api/donors Register a new blood donor with validation
PUT /api/donors/{id} Update donor profile information
DELETE /api/donors/{id} Delete donor and associated donation history
GET /api/donors/search Search available (non-cooldown) donors by blood group & city
GET /api/blood-groups List all 8 recognized blood groups (A+, B+, etc.)
GET /api/donations List donation history logs
POST /api/donations Record a new blood donation (enforces 90-day cooldown)
GET /api/dashboard Aggregated donor statistics, distribution, and recent logs
